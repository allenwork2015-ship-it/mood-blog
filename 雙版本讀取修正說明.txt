雙版本資料夾讀取修正｜2026-10-20

確認結果
正式版與測試版使用不同設定、IndexedDB 與待傳資料庫，未發現直接互相覆蓋。
Web Locks 僅在同一瀏覽器儲存環境與同一來源生效，Chrome 與 App 不能假設共用鎖；兩個原生選擇視窗與系統檔案服務仍可能受到宿主環境影響。
本次未在實際 Chrome＋App 的原生選擇視窗重現整台當機，不能宣稱已證明唯一原因或完全排除。

找到的程式問題
不支援直接讀寫資料夾的環境會改用唯讀選取。這條舊路徑針對每篇日記重掃整份 File 清單，並一次建立全部照片網址；先前本機壓力測試主要針對直接讀寫路徑，沒有涵蓋這條分支。
測試版也尚未具有正式版新增的照片暫存上限。

修正
1. 新增 local-folder-import.js：唯讀檔案清單只建立一次索引，沿用文字優先、照片按需讀取。
2. 正式版及測試版共用更新後的本機讀取模組，包含照片暫存回收、全數失敗保留原列表與延遲顯示進度。
3. 同一來源與同一瀏覽器儲存環境下，資料夾選取互斥；另一頁操作未完成時不再開第二個選擇視窗。
4. 選取階段寫入效能診斷 localFolder.selection；可分辨等待原生選擇視窗、等待唯讀選取、讀取中、保存設定或失敗。
5. 日記本按需讀取的照片不再沿用已被回收的舊暫存網址，保留現有編排與翻頁。
6. 正式版 Ver 16；日記本測試版維持非正式版本，不增加正式版號。沒有合併日記本到正式版。

已測試
隔離 Chrome，同一來源雙頁：第一頁選取期間，第二頁不呼叫選擇器；完成後可再次選取，各載入 100 篇。
獨立儲存環境：兩頁可同時載入，沒有應用程式迴圈。
兩頁同時唯讀匯入：各 500 篇日記、10,500 個 File 項目，僅讀 12 張目前封面，介面心跳持續運作。
日記本本機三種衝突選擇、備份、一般編輯交替、跨頁拖曳及原翻頁動畫通過回歸。
正式離線快取包含新模組，離線重開通過。
原生日誌選擇視窗使用模擬回傳測試，不等同實際 Chrome＋App 原生視窗測試；沒有存取使用者原始日記。

更新與實機確認
1. 正式版與日記本測試版都完整更新，各自放在不同程式資料夾，不要互相覆蓋。新的 local-folder-import.js 不可漏掉。
2. 關閉兩版舊分頁，先單獨重開正式版，確認 Ver 16；以少量日記副本測試一次。
3. 再單獨開測試版，用另一份少量副本測試；不要一開始就對相同原始資料夾雙開讀寫。
4. 兩邊單獨正常後，再以副本依序雙開；一邊完成選取後再操作另一邊。跨 App 不具共用選取鎖保證。
5. 若仍出現整個系統無法操作，請先停止雙開；記下是尚未看到選擇視窗、視窗尚未關閉，還是選取完成後。頁面尚能操作時匯出效能診斷，不需清除網站資料。
